# Security

This project has no formal security support or audit guarantee. Use the limitations documented in the README when deciding where to run it.

Never put real credentials, session tokens, personal records, or private database URLs into issues, commits, screenshots, or pull requests. Keep environment values in ignored local files or a deployment secret manager. Example files must contain placeholders only.

If GitHub's private vulnerability reporting option is available under the repository Security tab, use it for a sensitive report. Otherwise, open a minimal issue requesting a private reporting channel without exploit details or private data. No dedicated security email or response-time commitment has been established.

If a credential is exposed, revoke/rotate it at the provider first. Removing it in a later commit does not remove it from history. Coordinate any history rewrite explicitly with the owner.
